# Vera 網站全景架構

更新日期：2026-09-14（依公開網站與本機專案檔案對照）

本圖描述目前實際運作的網站架構；尚未公開的內容另行標示。後續工作見[網站任務清單](網站任務清單.md)，修改紀錄見[網站工作日誌](網站工作日誌.md)，文章原則見[內容經營系統](內容經營系統.md)。

## 一、網站定位

Vera 以沒有技術背景的實際使用者視角，記錄如何從真實問題出發，與 AI 一起拆解、嘗試、驗證與修正。網站不是工具排行榜或標準答案資料庫，核心價值是可供參考的真實過程與判斷。

## 二、訪客內容路徑

```text
首頁：從訪客正在遇到的問題出發
├─ 實踐案例
│  ├─ 工作流程與自動化
│  ├─ 人資與資料處理
│  ├─ AI 專案與內容製作
│  └─ 排錯與踩坑（跨主題篩選，與前三項可重疊）
├─ AI 協作思維
│  ├─ 說清楚真實情境
│  ├─ 不把 AI 回答直接當成事實
│  ├─ 能驗證就不只靠猜
│  ├─ 判斷方法是否適合
│  └─ 保留人的最後決定
├─ 工具使用筆記
│  ├─ 工具總覽與相關實踐案例（已公開）
│  └─ ChatGPT、Claude、Gemini 個別筆記（尚未公開）
├─ 關於 Vera
└─ 聯絡 Vera
   ├─ 電子郵件
   └─ Facebook 粉專
```

內容之間的主要關係：

```text
真實問題 → 實踐案例 → 驗證與修正 → 形成協作思維
                    └→ 累積工具使用筆記
```

「排錯與踩坑」是案例列表中的篩選方式，不是與前三項互斥的主題分類。公開工具總覽目前以選工具原則與相關案例為主；個別工具筆記未公開。

## 三、內容管理架構

```text
固定頁面
├─ index.md                 首頁
├─ ai-practice.md           實踐案例總覽與篩選
├─ ai-thinking.md           AI 協作思維
├─ ai-tools.md              工具使用筆記總覽（已公開）
├─ ai-tools-chatgpt.md      ChatGPT 工具筆記（未公開）
├─ ai-tools-claude.md       Claude 工具筆記（未公開）
├─ ai-tools-gemini.md       Gemini 工具筆記（未公開）
├─ about.md                 關於 Vera
├─ contact.md               聯絡 Vera
├─ privacy.md               隱私與網站說明
├─ 404.md                   找不到頁面時的返回入口
├─ robots.txt               搜尋引擎檢索規則
└─ sitemap.xml              搜尋引擎網站地圖

持續新增內容
├─ _posts/                  實踐案例文章；部分檔案設定為未來發布日期
└─ _templates/              新文章與工具筆記範本

共用網站元件
├─ _layouts/                頁面與文章版型
├─ _includes/               頁首與頁尾
└─ assets/                  CSS、文章圖卡與共用圖片

專案維護文件
├─ README.md                本機操作說明
└─ _docs/                   藍圖、內容原則、任務清單與工作日誌
```

目前個別工具筆記是根目錄的 `ai-tools-*.md` 頁面，均設為 `published: false`。`_config.yml` 仍保留 `tools` collection 設定，但目前沒有 `_tools/` 內容目錄；新增流程與範本已對齊現行根目錄頁面格式。

## 四、技術與發布架構

```text
本機 Markdown／HTML／CSS
        ↓
GitHub Repository（main）
        ↓
Jekyll 自動建置
        ↓
GitHub Pages 公開網站
```

補充的維運流程：

```text
設定未來日期的文章 → 每日排程請求重新建置 → 檢查公開頁面
公開網站 → Google Analytics 整體瀏覽資料 → 依資料輔助內容判斷
資料收集方式變動 → 檢查並更新隱私與網站說明
```

預排建置工作流程設定在 `.github/workflows/scheduled-pages-build.yml`；網站設定檔包含 Google Analytics ID，公開隱私頁也說明了分析工具。排程實際執行與搜尋引擎收錄情況不由此圖保證，需另查服務紀錄。

## 五、後續維護原則

1. 新內容先判斷是「實踐案例、協作思維或工具筆記」，避免重複建立分類。
2. 工具頁只公開已經有實際內容的頁面，不保留可被訪客進入的空白頁。
3. 每篇工具筆記應包含使用目的、適用任務、限制、驗證方式與目前判斷。
4. 新增文章後，同時檢查首頁精選、最近記錄、案例分類及相關內部連結。
5. 每次版面修改都檢查桌機與手機是否出現水平捲動、文字溢出或導覽遮擋。
6. 每篇實踐案例使用一致規格的專屬圖卡；同一張圖同時用於案例列表、文章首圖與社群分享預覽。
7. 正式文章圖卡優先使用 WebP；原始 PNG 保留作為可回復來源。
8. 安裝分析工具或新增資料收集功能時，同步更新隱私與網站說明。
9. 新增或移除公開頁面後，確認 Sitemap、導覽與 404 返回路徑仍然正確。
