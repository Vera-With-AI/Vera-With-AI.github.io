# Vera 網站全景架構

更新日期：2026-09-04

## 一、網站定位

Vera 以沒有技術背景的實際使用者視角，記錄如何從真實問題出發，與 AI 一起拆解、嘗試、驗證與修正。網站不是工具排行榜或標準答案資料庫，核心價值是可供參考的真實過程與判斷。

## 二、訪客內容路徑

```text
首頁：從訪客正在遇到的問題出發
├─ 實踐案例
│  ├─ 工作流程與自動化
│  ├─ 人資與資料處理
│  ├─ AI 專案與內容製作
│  └─ 排錯與踩坑
├─ AI 協作思維
│  ├─ 說清楚真實情境
│  ├─ 不把 AI 回答直接當成事實
│  ├─ 能驗證就不只靠猜
│  ├─ 判斷方法是否適合
│  └─ 保留人的最後決定
├─ 工具使用筆記
│  ├─ ChatGPT（已公開）
│  ├─ Claude（待完成，暫不公開）
│  └─ Gemini（待完成，暫不公開）
└─ 關於 Vera
```

內容之間的主要關係：

```text
真實問題 → 實踐案例 → 驗證與修正 → 形成協作思維
                    └→ 累積工具使用筆記
```

## 三、內容管理架構

```text
固定頁面
├─ index.md                 首頁
├─ ai-practice.md           實踐案例總覽
├─ ai-thinking.md           AI 協作思維
├─ ai-tools.md              工具使用筆記總覽
├─ ai-tools-chatgpt.md      ChatGPT 工具筆記
└─ about.md                 關於 Vera

持續新增內容
├─ _posts/                  實踐案例文章
└─ _templates/              新文章與工具筆記範本

共用網站元件
├─ _layouts/                頁面與文章版型
├─ _includes/               頁首與頁尾
└─ assets/                  CSS 與圖片
```

## 四、技術與發布架構

```text
本機 Markdown／HTML／CSS
        ↓
GitHub Repository（main）
        ↓
Jekyll 自動建置
        ↓
GitHub Pages 公開網站
```

## 五、後續維護原則

1. 新內容先判斷是「實踐案例、協作思維或工具筆記」，避免重複建立分類。
2. 工具頁只公開已經有實際內容的頁面，不保留可被訪客進入的空白頁。
3. 每篇工具筆記應包含使用目的、適用任務、限制、驗證方式與目前判斷。
4. 新增文章後，同時檢查首頁精選、最近記錄、案例分類及相關內部連結。
5. 每次版面修改都檢查桌機與手機是否出現水平捲動、文字溢出或導覽遮擋。
