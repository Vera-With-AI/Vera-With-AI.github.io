# Vera 網站內容經營系統

更新日期：2026-09-10

## 一、內容定位

Vera 不以「AI 專家教學」為定位，而是記錄沒有技術背景的人，如何從真實工作問題出發，與 AI 一起嘗試、驗證、修正與做出判斷。

每篇內容都應讓讀者至少帶走一件事：

1. 看見一個真實情境如何被處理。
2. 知道哪個地方需要驗證或保留判斷。
3. 能判斷這個經驗是否適合自己的情境。

## 二、固定內容主線

| 主線 | 適合寫什麼 | 目前已有內容 |
| --- | --- | --- |
| 工作流程與自動化 | 重複工作、流程設計、排程、權限與人工確認 | 週報、Gmail 草稿、人力成本排程 |
| 人資與資料處理 | 出勤、薪資、人力成本、Excel、資料驗證 | 出勤異常、人力成本、薪資結算 |
| AI 專案與內容製作 | 工具維護、教學設計、網站、內容與協作方式 | 模型下架、講義重整、個人網站 |

「AI 協作思維」與「工具使用筆記」是輔助內容：前者整理跨案例的判斷原則，後者只收錄已實際使用並能說明限制的工具。

## 三、每篇文章的最小結構

不必寫成制式教學；只要回答以下五件事即可：

1. **情境**：原本想完成什麼？限制或風險是什麼？
2. **嘗試**：用什麼工具或方法處理？
3. **卡點**：哪裡和預期不同？
4. **驗證與調整**：怎麼確認、修正或改變做法？
5. **目前判斷**：這個方法適合什麼情況、不適合什麼情況？

## 四、發布前清單

- [ ] 標題寫出「真實問題」或「核心判斷」，避免只有工具名稱。
- [ ] 摘要在兩到三句內說清楚情境與讀者可得到什麼。
- [ ] 選定一個既有主線作為 `topic`。
- [ ] 列出實際使用的工具，不放未使用的工具名稱。
- [ ] 製作一張 1733 × 908 的 WebP 文章圖卡，保留原始檔。
- [ ] 確認不含公司機密、不必要個資、帳號資訊或畫面中的敏感資料。
- [ ] 發布後檢查文章頁、首圖、相關文章與首頁最近記錄是否正常。

## 五、選題來源與優先順序

優先記錄「已完成一段實作、遇過轉折，而且能說明判斷」的事情，而不是為了更新而寫。

目前可發展、但要由 Vera 確認是否適合公開的選題：

1. 從 Google Search Console 驗證到 Sitemap：第一次讓個人網站被搜尋引擎理解。
2. 用 Google Analytics 看第一筆流量：個人網站上線後如何確認資料真的有進來。
3. 圖卡從 PNG 改 WebP：為什麼外觀幾乎不變，網站卻變快。
4. 首頁文章導覽調整：如何讓第一次來的讀者知道從哪裡開始。

## 六、建議節奏與檢查方式

不設定為了發文而發文的固定頻率。每完成一個值得記錄的專案或工作轉折，就先寫下情境、卡點與判斷，再決定是否整理成文章。

Analytics 有足夠資料後，每月看一次：

1. 哪些文章被閱讀最多。
2. 讀者從搜尋、Facebook 或直接連結而來的比例。
3. 首頁讀者最常點進哪一個內容入口。

用這些資料輔助選題，不用單靠流量決定網站方向。
